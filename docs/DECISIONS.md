# 決策紀錄

已經決定的設計取捨。要推翻某一項，請新增一筆並註明取代哪一筆，不要直接刪改舊的。

| 編號 | 日期 | 決定 | 原因 |
| --- | --- | --- | --- |
| D1 | 2026-11-12 | 摘要用訂閱制的 Claude CLI，不用按次計費的 API | 每週只有 1–4 份簡報，量很小；目標是零 API 費用 |
| D2 | 2026-11-12 | 程式負責抓檔、驗證、排版與結尾標註，模型只負責寫摘要 | 可預測、好測試，模型出錯時影響範圍小 |
| D3 | 2026-11-12 | 本地模型備援預設關閉；Claude 失敗就跳過並私訊維護者 | 小模型品質明顯較差，試跑期寧可不發也不要發差的 |
| D4 | 2026-11-12 | HTML 附件預設關閉 | 轉檔要用無頭瀏覽器執行附件裡的 JavaScript，有風險 |
| D5 | 2026-11-12 | 去重以貼文 ID 為準，不用簡報 ID | 講者延期後會隔週重貼同一個連結，需要重新摘要 |
| D6 | 2026-11-12 | 字數上限 400、不設硬性下限 | 重試時模型看不到圖，要求補字只會灌水或編造 |
| D7 | 2026-11-12 | 字數超標時把前一版 JSON 交給模型修改，不重新讀圖 | 快很多，也不會越改越偏 |
| D8 | 2026-11-12 | 重試中途失敗時，採用手上結構合法的版本，不改跑備援 | 稍微超字數的 Claude 摘要仍比備援模型好 |
| D9 | 2026-11-12 | 隔離用專用低權限帳號，不用 bubblewrap | bubblewrap 容易讓 CLI 啟動失敗，而且失敗時不明顯 |
| D10 | 2026-11-12 | 輸出掃到疑似憑證時，整則貼文不發，交給維護者檢查 | 代表簡報可能藏有指令，不該自動重試 |
| D11 | 2026-11-12 | 預設發到測試頻道，要手動改設定才會回覆到正式貼文 | 避免測試時誤發到正式頻道 |
| D12 | 2026-11-12 | Claude 最多看 32 頁，超過時抽樣並保留前兩頁與最後兩頁 | 多數簡報 20–40 頁可以全看；結論通常在最後 |
| D13 | 2026-11-13 | 需求、進度、決策都放在 repo 的 `docs/`，由 `CLAUDE.md` 要求每次工作前後讀寫 | 兩個人各自用 Claude 開發，需要單一的對齊來源 |
